# 本机测量与验证范围

测量日期：2026-10-26。环境为 Arch Linux / Niri 26.04 / 微信 Linux 4.1.13。通过保持连接的 MCP 客户端发送标注用途的中文消息到文件传输助手，并人工抽查截图。

## 分步调用的瓶颈

完整的观察、搜索联系人、准备、核对、发送流程约 104 秒，共 14 次调用。工具执行合计约 0.354 秒；单次窗口检查约 6 ms、截图约 47–53 ms、点击约 25–28 ms、剪贴板和按键约 4–5 ms。

调用间隔包含模型推理、识图、工具交付、进度说明与测试操作。没有模型服务内部计时，不能把全部间隔归为纯模型计算。

## 准确性实测

- 本轮两条短中文分区发送均核对正确，人工看图确认已出现。
- 聊天标题置信度约 96.5；两条消息识别置信度约 96.4、92.7。
- 一次真实菜单、一次真实几何变化均触发完整图后备；菜单存在时的发送请求没有发送。
- 新图核对后重新校准，状态读取恢复正常。
- 旧的含标点句子仍有 OCR 错字，被标记为不可靠；联系人列表也可能低置信。

不能把两个成功样本写成总体“100% 准确”。未知内嵌覆盖层、主题、字体、缩放和不同微信版本尚未全面覆盖。查看器与 AI 同时操作也不是保证不会互相影响；状态检查是减少误操作的措施。

## 自动化测试

当前包含 105 项隔离测试，覆盖（各轮历史测试数量见下文）：

- 模板语法、新安装所需模块和 OCR 资源、更新保留账号/配置/凭据/校准。
- 聊天变化、草稿变化、一次性 token 与发送后截图失败。
- 低置信标题、错误联系人、持久化请求去重和不确定请求不重发。
- 区域像素缓存、稳定标记变化、窗口几何和弹窗后备。
- 查看器打开时 AI 仍可操作、两个自动动作不能同时执行。

这些测试不连接真实微信，也不能替代新机器上的安装、扫码和界面验收。性能报告不包含聊天截图、二维码、聊天正文或登录态。
